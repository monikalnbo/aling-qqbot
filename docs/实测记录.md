### 0.4 真实 DeepSeek 端点是否可达

**结论：端点可达、鉴权链路正确，但没有可用 Key，因此没有发生一次成功的真实生成。**

把 provider 指回官方地址、故意填一个无效 key，走同一条链路：

```
LLM 响应错误: All chat models failed: AuthenticationError: Error code: 401 -
Authentication Fails, Your api key: ****real is invalid (request_id: 0483793d-...)
```

（`evidence/astrbot_real_deepseek_401.log`）

这个 401 是 **DeepSeek 服务端返回的**，说明：AstrBot → api.deepseek.com 网络通、请求格式对、Bearer 头带上了。**唯独缺一个有效 Key。** 换成真 Key 后同一条路就能出话，不需要改代码。

### 0.5 实测踩到的坑（都已写进 `docs/上手说明.md`）

| # | 坑 | 现象 | 处理 |
| --- | --- | --- | --- |
| 1 | provider 的 `key` 是空列表 `[]` | 启动日志 `Failed to instantiate provider adapter ... Missing credentials`，但**进程不崩**，发消息才报错 | key 必须非空；用 `$DEEPSEEK_API_KEY` 引用环境变量 |
| 2 | 反向 WS URL 少 `/ws` | NapCat 一直连不上 | `ws://<host>:6199/ws`，路径不能省 |
| 3 | 缺少 `X-Self-ID` / `X-Client-Role: Universal` 头 | 自定义客户端握手被拒（NapCat 自己会带） | 自写客户端必须补这两个头 |
| 4 | 配置被自动迁移 | 手改 `provider` 段不生效，`api_base` 其实跑到了 `provider_sources` | WebUI 改最稳；手改要同时看两段 |
| 5 | `cmd_config.json` 带 UTF-8 BOM | `json.load` 报 `Unexpected UTF-8 BOM` | 用 `encoding="utf-8-sig"` |
| 6 | `enable_id_white_list` 默认可能为开 | 消息全被静默丢弃，日志有事件无回复 | 显式设为 `false` |
| 7 | 群里上下文按会话隔离 | 群聊第一句 `历史=0`，看起来像记忆没生效 | 预期行为：不同群/用户互不串台 |
| 8 | Docker 里 `127.0.0.1` 指向自己 | NapCat 容器连不上 AstrBot | 同网络用服务名 `ws://astrbot:6199/ws` |
| 9 | WebUI 初始密码只打印一次 | 重启后日志里看不到了，登录不了 | 第一次见到就改密码；丢了只能删 `data/` 重新初始化 |

## 7. 语音合成接口实测（2026-11-12 09:00-09:15）

目标是让阿凌用用户给的通义 TTS（`qwen-audio-3.0-tts-flash` @ `https://maas.qianwenaiapi.com`）发语音。

### 7.1 调用方式矩阵

| # | 请求 | 结果 |
| --- | --- | --- |
| 1 | `POST /compatible-mode/v1/audio/speech`，OpenAI 风格 `{model,input,voice,response_format}` | **404** 端点不存在 |
| 2 | `POST /compatible-mode/v1/chat/completions` `{model,modalities:["text","audio"],audio:{voice:"Serena",format:"wav"}}` | **400** `url error, please check url` |
| 3 | 同上 + `stream:true` | 同上 400 |
| 4 | 同上，`voice` 提到顶层 | 400 `The voice property is required.`（说明该模型不认 `audio.voice`） |
| 5 | 换成 `qwen3-tts-flash`（models 列表里确实有）照抄 #2 | 400 `Due to invalid text, invalid audio was returned.` |
| 6 | `POST /api/v1/services/aigc/multimodal-generation/generation` `{input:{text,voice}}` | 200，给的是 OSS 链接（可用，但属另一套路径） |
| 7 | **`POST /api/v1/services/audio/tts/SpeechSynthesizer`** `{model, input:{text, voice:"longanfengyue", format:"wav", sample_rate:24000, volume:100}}` | **200**，`output.audio.url` → OSS，下载正常 |

结论：#7 是这台服务上 `qwen-audio-3.0-tts-flash` 唯一稳定的用法；音色必须用「龙安」系列，
填 `Serena`/`Cherry`（属 `qwen3-tts-flash`）会 400 `[cosyvoice:]Engine error [411]: TTS speak operation failed`。

### 7.2 音色

12 个系统音色逐个真调全部成功，清单见 `docs/音色清单.md`，脚本 `scripts/tts_voice_catalog.py`，
结果 `evidence/voice_enum_3.0.log`。选 `longanlingxi`（龙安灵希）。

### 7.3 音量

`volume` 是接口参数 `[0,100]`，默认 50。同一段文字实测：

| volume | 平均音量 | 峰值 | 文件大小 |
| --- | --- | --- | --- |
| 0 | -91.0 dB | -90.3 dB | 261164 |
| 25 | -26.4 dB | -8.3 dB | 261164 |
| 50 | -20.4 dB | -2.3 dB | 261164 |
| 75 | -16.9 dB | -0.0 dB | 261164 |
| 100 | -14.4 dB | 0.0 dB | 261164 |

文件大小完全一致、只有响度变化 → 服务端合成时就放大，不是事后二次处理。取 `100`。
（上表是 1.5s 短句 wav；交付样例是 11s 长句 mp3，50→100 差 6.0 dB，见 `evidence/voice_sample_meta.txt`。）

### 7.4 延迟

SpeechSynthesizer 非流式 POST ≈ 0.8 s，下载 ≈ 0.3 s；端到端（管理员发一句 → QQ record 发出）5.4 s，
其中大头是 DeepSeek 生成回复。
