# 更新记录：点歌改成查真歌词 + 唱不了的实话实说（插件 1.4.0）

日期：2026-11-16

## 这次解决什么

阿凌会唱歌之后，有两个毛病：

1. **歌词是模型现编的**。用户点《遇见》，她唱的是模型记忆里的句子，还可能记错、串词。查不到的歌（比如「不存在的歌名xyzabc」）她也会硬编一段，听上去像真的。
2. **歌名切分错**。「唱首孙燕姿的天黑黑」被解析成歌名=「孙燕姿的天黑黑」；「点歌 孙燕姿 遇见」只剩「孙燕姿」；「来一首孙燕姿的歌」也当成有一首叫《孙燕姿的歌》。

## 改了什么

### 1. 点歌先去真歌词库查原词

新增 `plugins/astrbot_plugin_aling_voice/lyrics.py`，流程：

- 从用户原话里抽 **歌名 + 歌手**（「唱首孙燕姿的天黑黑」→ 歌名 `天黑黑`，歌手 `孙燕姿`）；
- 先查 **QQ 音乐歌词接口**，查不到再查 **lrclib**；
- 用歌名 + 歌手给结果排序：同名不同歌手时优先选点名的歌手；标题完全不相关的（比如「ピカチュウ」）直接丢掉；
- 拿到 LRC 后剥掉抬头、作词作曲名单，按时间戳挑「开头 + 副歌」两段，每段 ≤40 字；
- 只给了歌手（「来一首孙燕姿的歌」）时**不再自作主张挑一首**，反问她「你想听哪首？」。

### 2. 查不到就如实说，别硬编

「唱首不存在的歌名xyzabc」现在会：

- 日志留 `sing-notfound title='不存在的歌名xyzabc' reason=两个歌词库都没有可用原词`；
- 语音里说清「这首原词我没查到」，并给两个选择：换一首 / 听她自己编一段（明确说是她编的）。

### 3. 开唱提示说清「词是原词、调子不是原曲」

在还没接上「按原曲调唱」之前，开唱前那句固定是：

> 行，我去查了《天黑黑》（孙燕姿）的原词；词是原词，调子是我自己编的，等我一下。

只给了歌手由她挑的，会多一句「你只说了歌手，我挑了这首」。

### 4. 顺手修的两个坑

- AstrBot 的 `on_llm_request` 钩子只 `await` 函数，**不遍历生成器**。之前在里面 `yield` 的主动消息一次都没发出去。改成 `await event.send(MessageChain([...]))` + `event.stop_event()`。
- `MessageChain` 的导入路径在 `astrbot.api.event`，不是 `astrbot.api.message`。

## 单元测试

`tests/test_lyrics.py`，10 条，网络全部 mock：

- 9 组「原话 → 歌名/歌手/是否明确」；
- 「孙燕姿的天黑黑」「这个不存在的东西」「孙燕姿的歌」三种切分；
- LRC 解析：抬头与作词作曲不念、时间戳正确；
- 选段：≤2 段、≤41 字、「天黑黑 欲落雨」这种以歌名开头的真歌词不被误删；
- 排序：无关标题丢弃、同名优先点名歌手；
- 查不到：两个库都空 → `ok=False`，reason 含「没有可用原词」；
- 只给歌手且 `allow_singer_pick=False` → reason「只给了歌手」。

运行：`10 passed`（`evidence/lyrics_source/after_pytest.log`）。

## 兼容性

- 日常说话的语音链路没动。
- 触发词规则没动（31 条正反例仍通过）。
- 只新增配置项：`lyrics_sources`、`lyrics_timeout`、`lyrics_allow_model_fallback`、`lyrics_allow_singer_pick`，默认值都对现网行为友好。
- 查歌词失败会自动退回原来的模型路径，不会吞消息。
