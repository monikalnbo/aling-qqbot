## 一、这件事到底需要什么

要「照原曲的调子唱」，必须凑齐两样东西，缺一不可：

1. **原曲旋律本身**，而且要是**音符序列**（每个音的音高 + 时值），不是一段给人听的歌。
2. **一个按音符序列发声的引擎**——业内叫「歌声合成」（SVS，Score-to-Singing / Score-to-Vocal）。
   它和你听歌识曲、语音合成不是一个东西：语音合成只能决定「说什么」，SVS 是「给谱子，按谱唱」。

所以「接一家第三方」不是换个接口地址那么简单，要求对方接口能收**音符/谱子**。
只接受「文字 + 参考音频」的商业接口，目前没有验证到有真能跟随旋律的。

## 二、两条腿的现状

### 腿一：拿原曲音符（阻塞）

| 途径 | 实测结果 |
|---|---|
| NetEase 搜歌 + 带时间轴歌词 | **可用**（《天黑黑》id 287749、236 秒；《遇见》id 287319、210 秒；《小星星》id 1451396976、74 秒） |
| NetEase 播放入口 | 返回 404 网页，**拿不到音频** |
| QQ 音乐歌词接口 | 可用，含逐行时间轴 |
| QQ 音乐取流 | `retcode 104009 invalidq`，**拿不到音频** |
| 酷狗搜索/播放 | 搜索可用（《天黑黑》hash `d4601c9f…`），播放接口返回 `url` 为空、`timeLength 0`，**拿不到音频** |
| 曲谱站（midishow） | 403 反爬，**拿不到** |

结论：**目前无法从公开渠道合法、稳定地拿到「某首歌的旋律数据或可分析音源」。**
没有旋律数据，后面再强的引擎也无从「照原曲唱」。

### 腿二：按谱唱的引擎

候选（都还没在本机验证）：

- DiffSinger 家族 ONNX 推理（`diffscope/dsinfer`、`HighCWu/DiffSinger-ONNX-Infer`）：输入就是音符 + 拼音/音素，CPU 可跑，中英文都支持
- espnet 中文歌声合成（OpenCpop 数据集系列）：有开源权重，但依赖 PyTorch，本机资源紧张
- SoulX-Singer ONNX：模型卡缺少说明，需要先看输入格式

本机条件：纯 CPU 8 核、可用内存约 1 GB、磁盘 13 GB 余量。**能跑小模型，但要先试。**

## 五、卡点与需要你拍板的两件事

1. **旋律数据来源**。公开接口目前都拿不到原曲音频或曲谱。可选：
   - 你提供曲谱/MIDI（或允许我去找要授权的谱源）；
   - 或建一个「人工确认的曲库」：只收录预先核对过的几首歌（如《小星星》《两只老虎》这类有公认简谱的），其余歌走「查不到就说查不到」；
   - 或走付费曲库/版权方接口（需要你给账号或预算）。
2. **本机跑 SVS 引擎**。要装 PyTorch/ONNX 运行时并常驻一个推理进程，占用磁盘与内存。
   现有 1 GB 可用内存下，需要严格控制模型大小；如果你不希望在这台服务器上加负载，
   那就只能回到「买商用按谱唱接口」这条路。

这两件不定，我继续往下走就是空转。**在你回复前，我不会改动线上点歌链路。**

## 六、和这次需求无关、但顺手查实的两个问题（等你确认后一起修）

1. **歌词现在是模型记忆，不是查库**。《天黑黑》只吐出「天黑黑 欲落雨。天黑黑 黑黑」，不是原词。
2. **歌名提取有 bug**：说「唱首孙燕姿的天黑黑」，抓到的歌名是「孙燕姿的天黑黑」，歌手名没剥掉，
   会原样塞进问句里，进一步降低歌词准确率。

这两条不管最后走 A 还是 B 都该修，修它们不影响曲调问题。
