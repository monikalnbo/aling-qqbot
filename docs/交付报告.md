## 四、实测发现的关键坑（详细见 实测记录 0.5）

1. Provider 的 `key: []` 会导致 `Missing credentials` —— 进程不崩，只让大模型静默不可用，极易误判为链路故障。
2. 反向 WS 的 URL **必须带 `/ws`**。
3. 自写客户端必须带 `X-Self-ID`、`X-Client-Role: Universal` 两个头（NapCat 自动带）。
4. Provider 配置会被迁移到 `provider_sources`，手改 `cmd_config.json` 要同时看两段。
5. `cmd_config.json` 是 **UTF-8 BOM**，要用 `utf-8-sig` 读写。
6. `enable_id_white_list` 若不是 `false`，消息会被**静默丢弃**。
7. 群聊上下文按群/用户隔离（不是 bug）。
8. Docker 内互连要用服务名 `ws://astrbot:6199/ws`，不能用 `127.0.0.1`。
9. AstrBot WebUI 初始随机密码只在首次启动日志出现一次。

4. 实测它音量 -12.0 dB，是 12 个里第二响的（仅次于顽皮少年音），配合 `volume=100` 不需要额外处理就够亮。

### 8.3 音量：`volume=100`（接口原生参数，不是事后二次放大）

- 百炼这个模型的 `volume` 是**接口参数**，取值范围 `[0, 100]`，默认 `50`；服务端合成时就把波形放大好。
- 实测同一段文字的响度：`volume=0` → -91.0 dB（静音）、`25` → -26.4、`50` → -20.4、`75` → -16.9、`100` → -14.4。
  本次把默认值从接口默认的 50 提到 100，**响度提升 6.0 dB（约等于响一倍）**。
- 关键证据：`volume=50` 与 `volume=100` 生成的文件**大小完全相同**（223771 字节）、时长完全相同（11.184 s），只有响度不同 —— 证明是接口端合成时就调大的，不是本地拿 ffmpeg 再放一遍。
- 文件：`evidence/voice_volume_v50.mp3` / `evidence/voice_volume_v100.mp3`、`evidence/voice_volume_test.log`。
