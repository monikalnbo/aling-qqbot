## 一、做了什么

### 1. 唱歌意图识别（新文件 `plugins/astrbot_plugin_aling_voice/sing.py`）

- **先判「不是唱歌」再判「是唱歌」**，宁可不唱，不要乱唱：
  - 否定：「不要唱歌」「别唱了」「不想听歌」→ 不唱
  - 反问：「你会唱歌吗」「能唱一首吗」→ 不唱（问她会不会，不是点歌）
  - 评价：「唱得真好听」「谁在唱歌」「教我唱歌」→ 不唱
- 正例（实测都触发）：`唱歌`、`唱首歌`、`唱首小星星`、`唱首《两只老虎》`、`来一首两只老虎`、`点歌 茉莉花`、`给我唱一段`、`来一首吧`
- 歌名自动抽取：书名号、曲目名、常见句式都认。
- **可配置**：
  - `sing_enabled`：唱歌总开关（`/唱歌 关闭` / `/唱歌 开启` 也能切，管理员）
  - `sing_auto`：聊天里自动识别点歌；关掉后只能用 `/唱歌` 口令
  - `sing_extra_words`：追加「算作点歌」的词（如 `["高歌一曲"]`）
  - `sing_extra_regex`：追加识别正则

### 2. 唱歌链路（`main.py`）

```
用户点歌
  → sing.py 判断意图、抽歌名
  → 给这一轮对话临时加「只输出歌词」的提示（不写进人设、不进历史）
  → DeepSeek 写歌词（儿歌/公共领域，最多 2 段、每段 ≤40 字）
  → prepare_lyrics 清理（去歌名、去动作、去解释、截断）
  → 每段调 qwen-audio-3.1-tts-next + 唱法提示（text_prompt）合成
  → 按原有分段机制，一段一条 QQ 语音发出
```

- 唱法提示默认：`请用唱歌的方式，带着旋律把这段歌词唱出来，像在唱儿歌一样，每个字拖长、有起伏地演唱`（`sing_prompt`，可改）。
- 歌词**由对话大脑自己写**，不是硬编码曲库；公共歌曲有版本差异，听到的不一定是你印象里那一版。
- 长歌自动分段：40 字 × 2 段，每段各一条语音，按顺序发（每段实测约 45 秒音频）。
- 合成失败（接口没给音频/超时）会写日志并**退回普通语音链路**，不会把消息吞掉。

### 3. `/唱歌` 口令

- `/唱歌 两只老虎`：指定歌名（最稳，绕开自动识别）
- `/唱歌`：不指定，由她自己挑
- `/唱歌 关闭`、`/唱歌 开启`：管理员开关
- `/语音状态` 现在也会告诉你唱歌开没开。

### 4. 文档

- `README.md`：新增「最新更新：会唱歌了」。
- `docs/上手说明.md`：新增 §12.9「让阿凌唱歌」，含说法表、等待时间表、配置项、排查表、回滚步骤。

## 二、解决了什么

1. **原来「会说」不等于「会唱」。** 老链路 `qwen-audio-3.0-tts-flash` 只会把歌词**念**出来，怎么加提示都没用（实测：念出来的音频稳定长音 0 个）。换成 `qwen-audio-3.1-tts-next` + 唱法提示后，同一句「一闪一闪亮晶晶 满天都是小星星」变成 45 秒的歌声，稳定长音段 47 个。
2. **日常聊天不能被拖慢。** 两条链路完全分开：聊天还是 3.0-flash（单段约 0.8 秒），只有点歌时才走 3.1-next（单段 58~83 秒）。实测普通聊天仍是 3~4 条短语音、8~17 秒内发完。
3. **不会乱唱。** 31 条正反例单测 + 端到端反例（「不要唱歌，聊聊天吧」→ 3 条普通语音、日志无点歌记录）。
4. **等太久不至于没反馈。** 点歌后先回一句「行，我去准备」，不会让你干等。

## 三、修了什么（实测中发现的问题）

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| `/唱歌 歌名` 把指令当歌名 | 提示语变成「《唱歌 两只老虎》」，日志 `title='唱歌 两只老虎'` | `message_str` 在群聊 @ 时仍带 `/` 唤醒前缀；新增 `_strip_cmd_prefix()`，先剥唤醒前缀再剥指令名。16 条解析用例（`tests/test_cmd_prefix.py`）全过 |
| 多段串行合成，整首容易超时 | 老实现逐段串行调接口，任何一段慢就整首失败 | 改为 `asyncio.Semaphore(2)` 受控并发 + 单段超时（`sing_timeout`，实测值 150 秒） |
| 歌词过长、段数过多 | 每段 30 字 × 4 段，合成久、容易撞超时 | 默认改成 **40 字 × 2 段**（配置 `sing_max_chars` / `sing_max_segments`） |
| 测量脚本把「唱」判成「念」 | 端到端日志里小星星先报「长音段 0」 | 测量算法与离线分析器统一（自相关峰值选择 + 中值滤波 + 0.6 半音容差长音段），复测 52 段/23.5 秒 |
| 端到端脚本把 `/唱歌` 结果判成「没收到音频」 | 指令段在合成完成前就停止等待 | 指令段单独给 90 秒静默窗口（长歌合成 90~160 秒），复跑通过 |
| 反例的「上一句漏跑的歌声」会串到下一句 | 测「你会唱歌吗」时收到一条 45 秒歌声，看起来像反例误触发 | 日志加了 `text=` 字段精确对账：这条歌声属于上一句排队中的点歌；脚本改成按完整回复判断、清掉过期音频文件，复跑 4 条反例全部为「念」 |

## 五、怎么让它唱你想听的歌

| 想听什么 | 就这么说 |
| --- | --- |
| 随便来一首 | `唱歌`、`唱首歌`、`来一首` |
| 指定歌 | `唱首小星星`、`唱首《生日快乐》`、`来一首两只老虎`、`点歌 茉莉花`、`唱一段送别` |
| 最稳（怕识别不到） | `/唱歌 两只老虎` |
| 临时关掉 | `/唱歌 关闭`（管理员），恢复：`/唱歌 开启` |

等待：单段约 40~75 秒出音频，两段的歌约 90~160 秒。点完先去干别的，她会发过来。

## 六、失败了怎么办

| 现象 | 先看这里 |
| --- | --- |
| 说了「唱首歌」没反应 | 是否在群里 @ 了她；`/语音状态` 看唱歌是否【关】；`sing_auto` 是否被关 |
| 回「行，我去准备」但很久没歌声 | 日志搜 `sing-synth` / `sing-fail`；失败会自动退回普通语音 |
| 只是念歌词没旋律 | 确认 `sing_model` 是 `qwen-audio-3.1-tts-next`（3.0-flash 不会唱） |
| 歌不对/唱一半 | 公共歌曲本身有版本差异；换说法指定更明确的歌名 |

日志：在服务器上查 AstrBot 最近 10 分钟的日志，过滤 `aling-voice`（关键行：`sing-intent` / `sing-done` / `sing-fail` / `sing-synth`）。
