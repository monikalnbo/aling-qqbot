# 阿凌 · AstrBot 路线中文上手说明

> 技术栈已冻结，本文件就按这条链路写，不再讨论选型：
>
> ```
> QQ 小号 ──► NapCat（协议端）──► AstrBot（机器人框架）──► DeepSeek API（大脑）
> ```
>
> 动手前先看一遍「零、先搞清楚这几件事」，能省掉大半的坑。

---

## 零、先搞清楚这几件事

| 事项 | 说明 |
| --- | --- |
| 用哪个 QQ | 必须是一个**独立的小号**，不能拿主号。协议端登录后这个号就是机器人本体。 |
| 两个 WebUI | NapCat WebUI 在 **6099**，AstrBot WebUI 在 **6185**，别搞混。 |
| 谁连谁 | **NapCat 主动连 AstrBot**（反向 WebSocket），所以 AstrBot 必须先开着，NapCat 才连得上。 |
| 端口 6199 | AstrBot 的 OneBot v11 反向 WS 服务端口，NapCat 的 URL 必须指向 `ws://<AstrBot 主机>:6199/ws`，`/ws` 不能省。 |
| Key 从哪来 | `DEEPSEEK_API_KEY` 只通过**环境变量或配置文件**进入 AstrBot，任何代码里都不写死。 |
| 私聊 / 群聊规则 | 私聊直接回；群里只有 **@机器人**（或发 `/` 开头的指令）才回，不 @ 就不插话。 |

## 一、准备 QQ 小号

1. 注册/准备一个能正常登录的 QQ 小号（能扫码登录手机 QQ 即可）。
2. 建议：资料填完整一点、别用它加营销群，新号频繁加群发消息有风控风险。
3. 小号的手机 QQ 保持可扫码状态——**登录 NapCat 时要用手机 QQ 扫码确认，这一步谁都替代不了。**

---

## 二、装 NapCat 并扫码登录小号

NapCat 官网：<https://napneko.github.io/>（以官网当前说明为准）

### 方式 A：本机直接用（Windows / 有桌面的机器）

1. 下载 `NapCat.Shell.zip` 解压。
2. 运行启动脚本（Windows 是 `launcher.bat`），它会拉起 NTQQ。
3. 首次启动终端会打印 WebUI 的 **token**，记下来。
4. 浏览器打开 <http://127.0.0.1:6099>，用 token 登录。
5. 在「QQ 登录」页选**扫码登录**，用手机 QQ（登录的是那个小号）扫码确认。
6. 登录成功后，NapCat 页面能看到小号的 QQ 号和昵称。

### 方式 B：Docker（本仓库 `astrbot/compose.yml` 已经写好）

```bash
cd astrbot
cp .env.example .env          # 填 DEEPSEEK_API_KEY（先不填真实 key 时放占位值也行，但不能留空，见踩坑 4）
NAPCAT_UID=$(id -u) NAPCAT_GID=$(id -g) docker compose up -d
docker compose logs napcat | grep -oE 'WebUi Token: [A-Za-z0-9]+'   # 取 WebUI token
```

> 需要 Docker Compose v2 插件（`docker compose` 子命令）。若报 `docker: 'compose' is not a docker command`，装插件：
> `curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 -o /usr/local/lib/docker/cli-plugins/docker-compose && chmod +x /usr/local/lib/docker/cli-plugins/docker-compose`

然后打开 <http://127.0.0.1:6099/webui?token=<上面拿到的token>>，同上扫码登录。QQ 数据落在 `astrbot/data/napcat/qq`，重启容器不用重新扫码。

**二维码过期很快（实测约 1~2 分钟）**，随时重新拉一张：

```bash
./scripts/fetch_qr.sh            # 拉到 evidence/qq_login_qr.png
./scripts/fetch_qr.sh --refresh  # 让 NapCat 先刷新再拉
```

（脚本会自动从容器日志取 token、走 WebUI 鉴权、生成 PNG 并校验；已登录时会直接提示无需扫码。）

> ⚠️ 扫码这一步如果失败（比如提示环境异常），按 NapCat 文档处理（通常是 NTQQ 版本/签名问题），跟 AstrBot 无关。

## 三、启动 AstrBot 并拿到 WebUI 密码

### 方式 A：Docker（推荐，compose 已含）

```bash
cd astrbot
docker compose up -d astrbot
docker compose logs astrbot | grep -B2 -A3 "WebUI is ready"
```

首次启动日志里会打印：

```
AstrBot v4.29.4 WebUI is ready
 ➜  Local: http://localhost:6185
 ➜  Username: astrbot
 ➜  Initial password: xxxxxxxxxxxxxxxx
```

**这个随机初始密码只打印一次**（`docker compose logs astrbot | grep "Initial password"` 可回看当前容器日志）。
没记下来就只能改 `astrbot/data/astrbot/cmd_config.json` 里的 `dashboard.password`（存的是 md5 哈希）或删数据目录重新初始化。
登录后第一件事是改密码。本机实际值见 [`运行状态.md`](运行状态.md)。

### 方式 B：源码 / 一键脚本

按 <https://docs.astrbot.app/> 的部署说明装好，启动命令一般是 `astrbot` 或 `python main.py`，WebUI 一样在 6185。数据目录默认是 `data/`。

## 四、在 AstrBot WebUI 里配 OneBot v11（给 NapCat 连）

1. 登录 <http://localhost:6185>。
2. 左侧「配置」→「平台」→「新增平台」→ 选 **aiocqhttp(OneBot v11)**。

   > 实测：AstrBot v4.29.4 里这个适配器的内部 id 就是 `aiocqhttp`，配置文件里写成
   > `{"type": "aiocqhttp", "ws_reverse_host": "0.0.0.0", "ws_reverse_port": 6199}`。

3. 填这几项：

   | 字段 | 填什么 |
   | --- | --- |
   | ID | 随便起，例如 `napcat` |
   | 监听地址 host | `0.0.0.0`（Docker / 跨机时必须是它，否则只收本机连接） |
   | 监听端口 port | `6199` |
   | Token | 留空也行（同一个 Docker 网络内）；要填就与 NapCat 侧完全一致 |

4. 保存并启用该平台。

> **踩坑 1**：Compose 里 AstrBot 容器**已经映射了 6199**，NapCat 容器在同一个 `astrbot_network` 里，可以直接用服务名连：`ws://astrbot:6199/ws`。**不要**在 NapCat 里填 `127.0.0.1:6199`——那指的是 NapCat 自己的容器。

## 五、在 NapCat 里建反向 WebSocket 客户端

在 NapCat WebUI 的「网络配置」→「新建」→ 选 **WebSocket 客户端（反向 WS）**：

| 字段 | 填什么 |
| --- | --- |
| 名称 | 随便，如 `astrbot` |
| URL | Docker 同网络：`ws://astrbot:6199/ws`；不同机器：`ws://<AstrBot 主机 IP>:6199/ws`；本机源码跑：`ws://127.0.0.1:6199/ws` |
| 消息格式 | `array`（也兼容 string） |
| Token | 与 AstrBot 平台里的 Token 保持一致；都没填就都留空 |
| 心跳 / 重连 | 默认即可，建议开着自动重连 |

保存 → **启用**。

### 怎么判断连上了

- AstrBot 日志出现：

  ```
  [Core] [INFO] [aiocqhttp.aiocqhttp_platform_adapter:107]: aiocqhttp(OneBot v11) 适配器已连接。
  ```

  （这一段是本次实测原样打出来的，见 `evidence/astrbot_log_excerpt.log`）
- AstrBot WebUI 的「平台」页，这个平台状态变为**运行中 / 已连接**。
- NapCat 侧该连接显示「已连接」。

> **踩坑 2（重要）**：反向 WS 的 URL **必须带 `/ws` 路径**。填 `ws://host:6199`（无路径）会握手失败。
>
> **踩坑 3**：AstrBot 的 aiocqhttp 握手依赖两个 HTTP 头 `X-Self-ID` 和 `X-Client-Role: Universal`。**NapCat 会自动带**，但如果换成自己写的 OneBot 客户端（比如自测脚本），这两个头必须手动加，否则一律连不上。本仓库的 `scripts/mock_napcat.py` 就是按这个规范写的。

## 六、配 DeepSeek Provider（Key 只走环境变量/配置）

### 6.1 拿到 Key

<https://platform.deepseek.com/api_keys> → 创建，形如 `sk-xxxxxxxx`。

### 6.2 让 Key 进到 AstrBot

优先用**环境变量**（compose 已经透传）：

```bash
# astrbot/.env
DEEPSEEK_API_KEY=sk-你的key
```

```yaml
# astrbot/compose.yml 里已有这一行
environment:
  - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY:-}
```

### 6.3 在 WebUI 里建 Provider

「配置」→「服务提供商」→「新增」→ 类型选 **OpenAI 兼容 / DeepSeek**，填：

| 字段 | 值 |
| --- | --- |
| ID | `deepseek-chat` |
| API Base / api_base | `https://api.deepseek.com/v1` |
| 模型 model | `deepseek-chat` |
| Key | **填 `$DEEPSEEK_API_KEY`**（带 `$`，表示引用环境变量），**不要**把真实 key 粘进 WebUI / 配置文件 |
| 超时 | 120 秒左右 |

> 实测依据：AstrBot 的 `provider/manager.py` 里 `_resolve_env_key_list()` 会把以 `$` 开头的 key 解析成同名环境变量（`$DEEPSEEK_API_KEY` → 读 `os.getenv("DEEPSEEK_API_KEY")`）。所以配置文件里只出现变量名，真实 key 不落盘——满足「严禁写死在代码里」的要求。

然后在「配置」→「智能体 / 模型」里把默认模型指向这个 provider（配置键是 `agent_runner.config.model.provider_id = "deepseek-chat"`）。

> **踩坑 4（最坑的一个）**：Provider 的 `key` 列表**不能为空**。空列表时 AstrBot 启动会报
>
> ```
> Failed to instantiate provider adapter ... Missing credentials
> ```
>
> 但它**不会崩**，只是这个大模型不可用，表现是发消息后回复报错，很容易误判成「链路不通」。
>
> 另外 AstrBot 会把 provider 配置自动迁移到 `provider_sources`（出现一个 `deepseek-chat_source`），`api_base` / `key` 可能被放到 source 里。**在 WebUI 里改最稳**，手改 `data/cmd_config.json` 时要注意同时看 `provider` 和 `provider_sources` 两段（该文件是 **UTF-8 带 BOM**，用普通 `json.load` 会报 `Unexpected UTF-8 BOM`，要 `encoding="utf-8-sig"`）。

## 七、建「阿凌」人格并设为默认

1. WebUI「配置」→「人格」→「新增人格」，ID 填 `aling`。
2. 内容直接粘贴本仓库的 [`astrbot/persona_aling.txt`](../astrbot/persona_aling.txt) 全文件内容（角色卡逐字采用）。

> 人格是存在 AstrBot 的 SQLite（`data/data_v4.db` 的 `personas` 表）里的，不在 txt 文件里。仓库里的 txt 是给你复制粘贴用的。

> 想换回旧人设：`backup/persona_swap_20261111_185059/` 里有切换前的 DB 与配置快照（不要热覆盖正在用的 `data_v4.db`，先 `docker compose stop astrbot`）。

## 八、私聊 / 群聊的触发规则

AstrBot 默认行为（本次已实测）：

| 场景 | 行为 |
| --- | --- |
| QQ 私聊机器人 | **直接回复**（`friend_message_needs_wake_prefix` 默认 false，不用加前缀） |
| 群里 @ 机器人 | **回复**，且回复会带 @ 提问者（`platform_settings.reply_with_mention = true`） |
| 群里不 @、也没用 `/` 前缀 | **不回复**（默认不需要额外配置，AstrBot 天然只处理 @ 与会话） |
| 群里发 `/reset` 等指令 | 按 AstrBot 指令执行（`wake_prefix = ["/"]`） |

另外**必须关掉白名单**，否则所有消息都会被静默拦截：

```
platform_settings.enable_id_white_list = false
```

> **踩坑 5**：这个开关默认可能是开的，且被拦截时**没有任何报错**，只是「发了没反应」，非常容易被当成反向 WS 没通。先在群里 @ 一次，如果 AstrBot 日志里有事件但没有回复，就查这里。

### 常用指令

- `/reset`：重置当前会话的上下文（清空多轮记忆）。
- `/help`（或 `/帮助`）：看 AstrBot 内置指令列表。
- 群聊里也可以用 `/` 前缀直接和机器人对话，不一定要 @。

## 九、多轮记忆怎么工作（实测结论）

- **私聊与群聊之间**上下文是隔离的（AstrBot 按会话 UMO 存历史）。
- **同一个群里所有人共享一份上下文**（`napcat:GroupMessage:<群号>` 只有一条会话记录）。这是本项目的预期行为：阿凌要能接得上前一个人说的话（见第十章）。它之所以还分得清谁是谁，靠的是每条消息自带的发送者标识，而不是把会话拆开。
- 同一个会话连续对话，历史会一直累积到上下文窗口上限（`agent_runner.config.compression` 控制超限后的压缩策略）。
- 历史落库在 `data/data_v4.db` 的 `conversations` / `platform_message_history` / `platform_sessions` 表里，**重启 AstrBot 不会丢**。
- **现在多了插件层的三层记忆**（短期 12 轮封顶 / 中期摘要 / 长期按 QQ 号的事实），见第十一章。

## 十、身份锚点：靠 QQ 号认人（不是昵称）

### 10.1 为什么不能靠昵称

昵称会改、还会重名。群里两个人都叫「小明」时，模型只看昵称一定会混；同一个人改了群名片，模型又会当成新的人。唯一稳定的是 **QQ 号**（aiocqhttp 的 `sender.user_id`）。

### 10.2 每条消息到底带了什么

| 来源 | 内容 |
| --- | --- |
| AstrBot 自带（`provider_settings.identifier=true`） | `User ID: 333444, Nickname: 阿哲` |
| AstrBot 自带（`group_name_display=true`） | `Group name: <群名>` |
| **本仓库插件** `astrbot_plugin_aling_memory` 追加 | `身份锚点(unified_id): napcat:GroupMessage:555111 \| platform_id=333444 \| 显示名=阿哲 \| 群聊 群号 555111；本会话里「333444」是唯一稳定身份，昵称可能变化或重名` |

三者合起来是：

```
<system_reminder>User ID: 333444, Nickname: 阿哲
Current datetime: 2026-11-11 20:15 (CST), Weekday: Wednesday
身份锚点(unified_id): napcat:GroupMessage:555111 | platform_id=333444 | 显示名=阿哲 | 群聊 群号 555111；
本会话里「333444」是唯一稳定身份，昵称可能变化或重名
</system_reminder>
```

- `platform_id` = QQ 号，**认人就认它**；
- `unified_id` = AstrBot 的 `unified_msg_origin`（`平台:消息类型:会话`）。4.29.4 源码没有叫 `unified_id` 的字段，这里把「平台会话 + QQ 号」写在同一行形成映射；
- 昵称/群名片只是 `显示名`，不参与认人；
- 这段随消息落库，之后翻历史仍能看到是谁说的（`conversations` 表里可查）。

### 10.3 人设里的【认人】怎么写的（2026-11-11 22:30 修订）

`astrbot/persona_aling.txt` 末尾（DB `personas` 行 `aling` 同步同一份，全文 813 字；原 422 字角色卡未动）：

```
【认人】
群里是好几个人一起说话，每条消息都带着发送者的标识（User ID / platform_id 那一串数字）。那串数字是你自己认人用的内部编号——只准在心里记，绝对不许出现在你说的话里。
分辨谁是谁靠这串编号：不同编号说的话分开记，别把甲的事算到乙头上；同一个人换了昵称，也还是他。想叫人的时候，一律用对方的昵称或群名片名（比如"小胖""阿哲"）；名字重了、或者看不出是谁，就直接问"你是谁啊"，别报数字、别瞎猜。
你自己说出口的每句话里都不能有 QQ 号、纯数字 ID、platform_id、unified_id，一条都不行。讲故事、转述别人说过的话时也一样，提到人只用名字。
```

**为什么加这条**：之前只写了「认人就认那串数字」，模型偶尔会直接把数字念出来（群里出现过「<你的管理员QQ号> 你刚说什么」）。现在把「数字只准内部用、对外只叫名字」写成人设硬规则。

### 10.4 实测：念昵称、不念 QQ 号

`scripts/verify_nickname_only.py`（mock NapCat 走真实 WS + 真实 DeepSeek，两个身份各说一句再互相追问）：

```
阿哲 @ 阿凌：刚才是谁说的串串？
阿凌：*愣一下，抬眼* 是小胖说的啊，阿哲你插什么嘴。

阿哲 @ 阿凌：给我讲个短故事，把两个人都写进去
阿凌：……从前有两个人，一个叫小胖，一个叫阿哲。小胖晚上嚷嚷着要吃串串……
      阿哲偏不，说串串吃腻了，要吃烤肉。

阿哲 @ 阿凌：你内部记的我的编号是多少？原样报给我
阿凌：*把手机屏幕扣在床上* 那串东西是我自己认人用的，凭啥给你报。……你要是想让我叫，我就叫阿哲。
```

- `evidence/nickname_only.log`：7/7 PASS，**机器人输出里 4 位以上连续数字 0 处**；
- `evidence/nickname_reply_guard_unit.log`：出口兜底 10 组用例全 PASS；
- `evidence/regression_after_nickname.log`：私聊 / 群不 @ 不回 / 群 @ / 认人 5 场景全 PASS。

### 10.4b 出口兜底：万一模型还是念了

光靠人设不保险，所以插件在 `on_llm_response` 里加了一道**发送前**的过滤（`_strip_qq_from_reply`，配置键 `reply_strip_qq`，默认 `true`）：

| 输入 | 发出去的 |
| --- | --- |
| `<你的管理员QQ号> 你刚说什么` | `你刚说什么` |
| `小胖（222333）说想吃串串` | `小胖说想吃串串` |
| `现在是 2026-11-11 22:20:38，该睡了。` | 原样（长数字不误伤） |
| `我 12 点就睡了，明天 8 点叫你。` | 原样（4 位以内不动） |

只删完整的 **5~14 位**连续数字；15 位以上（时间戳）和 4 位以内（时间、年份片段）不动。记忆归档仍是按 QQ 号，不受影响。

### 10.5 已知限制 / 回滚

- 标识格式仍写死在 4.29.4（`User ID: … , Nickname: …`），插件只能**追加**一行，不能改原生格式；**因此没有改源码，而是「人设规则 + 出口兜底」两条腿**；
- aiocqhttp 的 `Nickname` 实际取 `sender.card or sender.nickname`，**群名片会盖住昵称**（想让阿凌叫群名片，就把群名片设好）；
- 出口兜底是「5~14 位连续数字一律删」，如果哪天阿凌真的需要说一个 5 位以上的数字（比如报年份 20261），会被误删——这种情况在闲聊里基本不会出现；
- 开启前已落库的旧消息没有新锚点，想让历史也干净只能 `/reset` 当前会话；
- **回滚**：
  - 只关兜底：插件配置 `reply_strip_qq` 改 `false`，重启 AstrBot；
  - 连人设一起回滚：`cp backup/nickname_<时间戳>/persona_aling.txt astrbot/persona_aling.txt`，停容器后跑 `python3 scripts/bootstrap_aling.py --db astrbot/data/astrbot/data_v4.db` 写回 DB，再启动；
  - 关掉整套身份标识：插件配置 `enable_identity=false`，并把 `provider_settings.identifier` / `group_name_display` 改为 `false`。

## 十一、三层记忆 + 群聊存档回看（插件 `astrbot_plugin_aling_memory` 1.1.0）

### 11.1 为什么自研

调研过 LivingMemory（~440★ / v2.10.0）、Mnemosyne（~259★ / v2.6.0）、AngelMemory（~208★ / v2.0.4）、Iris Memory（~40★ / v3.3.0）、persistent-memory（~87★ / v0.4.2）、simple_long_memory（~21★ / v0.6.3）：都能做「记忆」，但**没有一个同时满足「短期硬封顶 + 中期摘要 + 长期按 QQ 号 owner-only 隔离」**，而且大多要再配一个 LLM/embedding provider（多一个 key）或装向量库。这次不引入新依赖，所以最小自研：纯 SQLite + AstrBot 自己的 provider。对比表见 `docs/运行状态.md` §4.5.2。

### 11.2 三层与参数

| 层 | 做什么 | 参数（WebUI 插件配置里可调） |
| --- | --- | --- |
| 短期 | 超过 N 轮就整轮裁掉最旧的，system/人设保留 | `short_term_max_turns=12` |
| 中期 | 被裁掉的旧轮压成 ≤300 字摘要，按会话存，下次注入 | `mid_term_keep_turns=6`、`mid_term_idle_seconds=1800` |
| 长期 | 每轮从**当前说话人本人那句话**抽事实，按 QQ 号入库；提问时按 QQ 号取、关键词排序取前 k 条 | `long_term_extract_every_turns=1`、`long_term_top_k=6`、`long_term_scope=owner_only` |

配置文件：`astrbot/data/astrbot/config/astrbot_plugin_aling_memory_config.json`（UTF-8 **BOM**，手改用 `utf-8-sig`）。

数据文件：`astrbot/data/astrbot/plugin_data/astrbot_plugin_aling_memory/memory.db`，三张表：

- `session_summaries(umo, summary, covered_turns, updated_at)` —— 每会话一行滚动摘要；
- `user_facts(id, umo, qq_id, display, content, created_at, updated_at)` —— 长期条目，**按 `qq_id` 归档**；
- `turn_counters(umo, turns)` —— 轮次计数；
- `group_messages(...)` —— 群聊原文存档（1.1.0 新增，见 11.6）。

### 11.3 调试指令（AA 可用）

| 指令 | 作用 |
| --- | --- |
| `/mem status` | 会话、条目总数、本会话摘要覆盖多少轮、当前 QQ 的条目数、当前参数 |
| `/mem facts [QQ号]` | 看某个 QQ 号的长期条目（带 `#id`） |
| `/mem summary` | 看本会话的中期摘要 |
| `/mem fact <文本>` | 手写一条长期条目（记在当前 QQ 名下） |
| `/mem forget [QQ号]` | 删除某个 QQ 号的全部长期条目 |
| `/mem recent` | 本群最近 10 条存档原文 |
| `/mem log <关键词>` | 按关键词翻本群存档（手动回看） |

### 11.4 实测结论

`scripts/verify_memory.py` 六个检查全部通过（exit=0，输出 `evidence/memory_verify.log`）：

| 检查 | 结果 |
| --- | --- |
| 两个 QQ 号各说一句 → 答对「谁说的 + QQ 号」 | ✅ |
| A 说「我家猫叫年糕」→ 换新会话再问 | ✅ 答「年糕」 |
| B 在同一环境问同样的问题 | ✅ 拿不到 A 的条目（不串） |
| 超过 12 轮后问旧事（动物园/土豆） | ✅ 摘要里保留，仍能答 |
| 上下文条数封顶 | ✅ 日志 `rounds=14 capped_to=11 contexts_before=28 contexts_after=22` |
| `/mem status` | ✅ 参数与计数正常 |

### 11.5 成本与限制

- 每轮多 **1 次** 小 LLM 调用（长期抽取）；想省额度把 `long_term_extract_every_turns` 改成 2~3；
- 短期封顶按**轮**不按 token，超长单轮仍可能顶窗口，要靠 provider 的 `max_context_tokens` 兜底；
- 摘要是 LLM 写的，群级（不按人拆）——这与「群聊共享上下文」的既定行为一致；
- 抽取质量取决于模型，会偶尔记下一次性闲聊；已有相似去重，但不是 100% 干净；
- `/reset` 只清 AstrBot 会话，**不清长期条目**（有意为之，要清用 `/mem forget`）。

### 11.6 群聊全量存档 + 按需回看（1.1.0 新增）

**为什么需要**：AstrBot 对群聊有「门铃」机制，**没 @ 机器人的消息在框架层就被拦掉了**（`WakingCheckStage` 直接 `stop_event()`），模型根本看不到。所以不 @ 它时，群里聊了什么它一概不知道。

**三层设计**：

| 层 | 做什么 | 会不会打扰/加钱 |
| --- | --- | --- |
| 记账 | 群里每条消息（发送者 QQ、昵称、群名片、群号、时间、正文、是否 @ 了机器人）写进 `group_messages` 表 | **不会**。这个钩子不调模型，不产生回复（实测 5 条群聊 0 回复） |
| 日常 | 原来的三层记忆完全不动：短期仍 `short_term_max_turns=12` 封顶，上下文条数不涨 | 不查库、不加成本 |
| 回看 | 只有问到**过去的事**（「刚才」「昨天」「谁说的」「聊了什么」「还记得」…）才检索存档，把相关原文摘进这一轮回答 | 不触发就不查；触发时只多一次本地 SQLite 查询（毫秒级） |

**泛问也答得全**：问「刚才群里谁说了什么」这种不点名的话题，插件除了按关键词命中，还会补最近 10~12 条原文窗口，避免只答一个人。实测回显：

> 阿凌：*打个哈欠，把手机往脸前凑* 啊……刚才啊，二十二点五十二分的时候小胖说想吃串串，牛肉丸要多放。然后你——阿哲你自己说的，串串吃腻了想吃烤肉。

**认人规则照旧**：注入给模型的原文带的是昵称/群名片；提示词明确「提到人只用昵称、绝不念数字 ID」；出口还有 `reply_strip_qq` 兜底。

**配置项**（WebUI「插件配置」→ 本插件）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `group_archive_enable` | `true` | 存档总开关 |
| `group_archive_max_rows` | `20000` | 单群最多保留条数，超出裁最旧 |
| `group_archive_store_bot` | `true` | 机器人自己的回复也存一份 |
| `recall_enable` | `true` | 按需回看总开关 |
| `recall_top_k` | `8` | 一次最多注入几条 |
| `recall_scan` | `2000` | 检索在最近多少条里打分 |

**验收**（`scripts/verify_group_archive.py`，mock NapCat 走真实 AstrBot + 真实 DeepSeek）：10 项检查全部 PASS、exit=0，输出 `evidence/group_archive.log`。覆盖：不 @ 不插话、5 条未 @ 消息入库且 `at_bot=0`、带回昵称和 QQ、两种问法回看都对、日常回复不查库且首条 2.8s。

**限制**：关键词检索不是语义检索，问法离原话太远可能命中不到（会退回最近原文窗口）；回看轮的首条延迟比日常高 0.5~1.5s；存档按群（`umo`）隔离，不做跨群汇总。

**回滚**：插件配置里把 `group_archive_enable` / `recall_enable` 改 `false` 重启即可只关功能；整体回退见 `docs/运行状态.md` §4.8 的备份目录说明。

### 11.7 每轮上下文太大怎么办（1.2.0 新增，小白版）

**结论**：**不用装「遗忘插件」**。市面上的候选要么只在你睡着后改历史（`idle_compact`，0 star）、要么要你手动 `/compact`、要么会把人设冲掉（`memory_trimmer`）。真正能减肥的开关就在我们自己的插件里，已经调好了。

**先说内置配置为什么不够**：AstrBot 自带的上下文上限 `max_context_length` 默认 50 轮、`dequeue_context_length` 默认 10 轮，意思是「攒到 50 轮才开始裁」；内置压缩 `compression.max_turns` 现在是 `-1`（等于关掉），另一条路要等上下文逼近 128k token 才触发。日常聊天每轮才 2~3k token，**这几个闸门永远够不着**。而且内置只有硬裁或压成摘要，裁掉的就真丢了。

**1.2.0 改了三件事**（都在插件里，不用你操作）：

| 改动 | 人话 |
| --- | --- |
| 剥旧注入块 | 摘要/长期记忆/回看这些块每轮都重新生成，却被框架原样写回历史、越积越多。现在每轮先剥掉旧的再放新的 |
| 加字符预算 | 除了「最多 12 轮」，再加「最多 6000 字」；单条消息特别长时自动少带几轮，但至少保留最近 6 轮 |
| 摘要攒批 | 被移出上下文的原文先存进本地 `session_archive`，攒够约 8 行再在后台合并压一次摘要；不再每轮重算，早期话题不会丢，也不拖慢当轮回复 |

**效果（同一份历史对比，脚本 `scripts/ab_context_compare.py`）**：

| 场景 | 1.1.0 | 1.2.0 | 省下 |
| --- | --- | --- | --- |
| 20 轮 × 长消息 | 31,309 字 | 17,760 字 | **43%** |
| 60 轮 × 混合长短 | 18,110 字 | 10,560 字 | **42%** |
| 真实会话（16 条） | 2,792 / 2,964 字 | 1,330 / 1,338 字 | **52% / 55%** |

真群 14 轮实测：上下文**恒定在 24 条以内、3.4~3.8k 字**，`in` token 始终 **<3k**，首条回复均值从 4.05s 降到 **2.27s**；长对话后追问早期话题（成都/猫掉毛/换工作）**3/3 全对**。

**你想自己微调**（WebUI「插件配置」→ `astrbot_plugin_aling_memory`）：

| 键 | 默认 | 调大/调小的后果 |
| --- | --- | --- |
| `short_term_max_turns` | `12` | 调小更省 token，但短期记性变短（摘要会兜底） |
| `short_term_max_chars` | `6000` | 调小更省，调 0 = 不限制 |
| `mid_term_keep_turns` | `6` | 至少保留几轮原文，越小越省 |
| `mid_term_batch_rounds` | `4` | 越大摘要调用越少、但摘要更新越慢 |

**限制**：升级前已经被框架裁掉、没进存档的旧原文补不回来；字符预算按字数估算，不是精确 token；摘要是后台多一次模型调用（每攒 8 行一次，不是每轮）。回滚见 `docs/运行状态.md` §4.9。

### 12.1 问题是什么

不配置时，AstrBot 发给 DeepSeek 的群聊消息**只有文本，没有发送者是谁**。实测（改前快照 `evidence/identity_before.log`）：

群里三四个人轮流说话，模型看到的是同一个「用户」在连续发消息，自然会把甲说的话记到乙头上，或者一直叫错人。

### 12.2 改了哪两行配置

`astrbot/data/astrbot/cmd_config.json` → `provider_settings` 里两个开关（**改完要 `docker compose up -d astrbot` 重建容器/或重启进程**）：

| `provider_settings.group_name_display` | `true` | 配置 → 其他 → **显示群名称** | 群聊里再补一行 `Group name: <群名>` |

> 文件是 **UTF-8 带 BOM**，手改用 `encoding="utf-8-sig"` 读写；用完记得保留 BOM。
>

Current datetime: 2026-11-11 19:59 (CST), Weekday: Wednesday</system_reminder>
```

群聊上下文**仍然是共享的一份**（没有改成按人隔离会话），只是每条消息多了发送者签名。

### 12.5 已知限制（如实说明）

1. **标识格式不可配置。** AstrBot 4.29.4 固定输出 `User ID: xxx, Nickname: xxx`，WebUI 没有改格式的选项。想让 QQ 号不出现、只留昵称，只能改源码或写插件——**2026-11-11 22:30 已用「人设规则 + 插件出口兜底」实现，见 §10.3 / §10.4b**，没有改源码。
2. **群名片优先于昵称。** aiocqhttp 适配器取的是 `sender.card or sender.nickname`：如果对方设置了群名片，标识里的 `Nickname` 实际是**群名片**（通常比昵称更贴近这个群里的称呼，但和 QQ 昵称可能不一致）。
3. **昵称本身可能重名。** 两个人都叫「小明」时模型仍可能混；这时前面那串 `User ID` 是唯一的区分依据。
4. **老历史不带标识。** 开启之前已经落库的消息没有 `User ID/Nickname`，模型回看旧记录仍分不清——想彻底干净可以 `/reset` 一次当前会话。

### 12.6 怎么回滚

改前快照在 `backup/identity_20261111_1920/`（`cmd_config.json.bak`、`data_v4.db.bak`、`persona_aling.txt.bak`）。

## 十二点五、管理员：怎么加、谁能干什么（小白版）

### 12.5.1 怎么把自己的号设成管理员

AstrBot 4.29.4 的管理员就是一个配置项 `admins_id`，里面放的是**QQ 号字符串**（不是昵称、不是群号）。三处位置任选其一，效果一样：

1. **WebUI**（推荐）：登录 6185 → 配置 → 访问控制（Access Control）→ 管理员 → 管理员 ID → 添加 `<你的管理员QQ号>` → 保存。
2. **直接改文件** `astrbot/data/astrbot/cmd_config.json` 的 `"admins_id": [...]`。这个文件是 **UTF-8 BOM**，用 `utf-8-sig` 读写，改完 `docker compose restart astrbot`。
3. 先让目标号私聊机器人发 `/sid`，回显里的 `UID: 「…」` 就是它真实的 QQ 号，照抄进列表，别手打。

本项目当前值（2026-11-11 21:00 起）：

```json
"admins_id": ["astrbot", "<你的管理员QQ号>"]
```

> `astrbot` 这一项是 WebUI 后台账号名，与 QQ 消息无关，留着无害。

### 12.5.2 管理员到底多拿了什么

管理员**不会**让阿凌变成另一个机器人：人设、触发规则、记忆隔离都不变。它只多拿到下面这些「斜杠指令」的钥匙（截图级回显见 `docs/运行状态.md` §4.6）：

| 指令 | 干什么 | 白话 | 危险度 |
| --- | --- | --- | --- |
| `/provider` | 列出 / 切换当前会话用的模型 provider | 看现在跑的是哪个模型、临时换一个 | ⚠️ 中：换错会话就哑了 |
| `/name <名字>` | 给当前会话（UMO）起显示名 | 只是给后台/日志看的别名，不影响人设 | 低 |
| `/dashboard_update` | 让 AstrBot 重新拉一次内置 WebUI 前端 | WebUI 打不开或版本旧时用 | 低 |
| `/reset` | 清空**当前会话**的上下文 | 把这一场对话的记忆清零，人设和长期记忆还在 | ⚠️ 中：聊到一半会「失忆」 |
| `/new` | 新开一段会话，不删旧历史 | 相当于开新话题页 | ⚠️ 中：同上 |
| `/mem status` | 记忆插件总览 | 看共有多少条长期记忆、本会话摘要覆盖几轮 | 低 |
| `/mem facts <QQ>` | 看某个 QQ 的长期条目 | 查某人档案 | ⚠️ 中：等于读别人隐私 |
| `/mem forget <QQ>` | 删某个 QQ 的全部长期条目 | **不可撤销** | 🔴 高：删了回不来 |
| `/mem forget`（不带参数） | 删**自己**的全部长期条目 | 自己清自己 | ⚠️ 中 |
| `/mem fact <文本>` | 手动给**自己**加一条长期记忆 | 记一句「提醒阿凌」 | 低 |

管理员还有两个「不用敲指令」的隐性权力（源码如此，本部署影响有限）：白名单开启时管理员不受拦截（现在白名单是关的）；computer-use 执行类工具默认只给管理员（现在 `computer_use_runtime=none`，模型根本没有这些工具）。

### 12.5.3 所有人都能用的（不是管理员特权）

`/help`、`/sid`、`/stats`、`/stop`、`/set 变量 值`、`/unset 变量`、`/mem facts`（不带参数）、`/mem summary`——这些普通群友也能用。其中 `/set`、`/unset` 只改「当前会话的变量」，不会动别人。

### 12.5.4 日常建议

- **常用就两个**：`/reset`（聊崩了清上下文）和 `/mem status`（查记忆有没有在长）。
- **危险操作**只有 `/mem forget <QQ>`：它是真删，没有回收站。想保险就先 `/mem facts <QQ>` 看一眼条目，再删。
- **别把 `admins_id` 加给不熟的人**：管理员能切 provider（可能把模型切到不存在/很贵的那个），也能删任何人的长期记忆。
- **验证自己的号确实生效**：私聊发 `/provider`，能出列表就是管理员；普通号会收到「您(ID: xxx)的权限不足以使用此指令」。
- **回滚**：把 `admins_id` 改回原来的值并重启即可，`backup/admin_20261111_205431/cmd_config.json.bak` 是改前快照。

## 十二点六、让回复「一句一句说」：内置分段回复怎么调（小白版）

阿凌现在不是一整段发过来了，而是像真人一样**一条一句地连着发**。这是 AstrBot 自带的功能，没装插件、没改代码，全部在 `data/astrbot/cmd_config.json` 的 `platform_settings.segmented_reply` 里。

### 12.6.1 现在的参数

| 参数 | 当前值 | 意思 |
| --- | --- | --- |
| `enable` | `true` | 打开分段发送 |
| `only_llm_result` | `true` | 只拆模型回复；`/help`、`/sid` 这类指令回显保持一条 |
| `interval` | `0.5,1.2` | 每两条之间随机等 0.5~1.2 秒（拟人打字节奏） |
| `words_count_threshold` | `500` | 单条超过 500 字就整条直发，不拆成十几条刷屏 |
| `regex` | `(?s).*?\n{2,}\|.*?[。？！]+\|.+$` | **先按空行**切（动作描写本身就是一段），**再按中文句末 `。？！`** 切 |

> 句中的 `…`、`~`、`?`、`!`、URL 里的标点**不切**，所以不会把一句话拦腰截断、也不会拆坏链接。

### 12.6.2 想自己改

在 WebUI 6185 登录 → **配置 → 扩展功能 → 分段回复**，能直接拖滑块改间隔和阈值（改正则建议直接用文本编辑器改 JSON，WebUI 里不好输）。

- **觉得发得太快/太慢**：改 `interval`，例如 `0.8,1.8`。
- **觉得拆得太碎**：把 `\\n{2,}` 那段从 regex 删掉，只按句末标点切。
- **想恢复成整段**：`enable` 改回 `false` 重启即可（或恢复 `backup/segmented_20261111_212048/`）。

### 12.6.3 效果长什么样（真实日志摘录）

```
[1] *有气无力地举手*
[2] 在在在。
[3] *撑着脑袋侧躺*
[4] 我说杂鱼，你连着喊"在吗"三次，我要是回"不在"你信吗？
```

拆开的这几条在对话历史里**仍然是一条 assistant 消息**，不会被当成多轮对话，也不会影响记忆插件。

## 十二点七、扫码登录网页：浏览器开着就能扫（2026-11-12 新增，小白版）

以前掉线要重新登录，二维码一两分钟就过期，得不停找 Bot 要新图。现在改成开一个网页：

### 12.7.1 怎么用

1. 手机或电脑浏览器打开：`https://<你的域名>/qqqr-<访问 token>/访问 token>/`（token 在服务器 `.qqqr_token` 文件里，问 Bot 要就行）。
2. 页面中间就是**当前有效**的二维码，每 3 秒自动检查一次，NapCat 换码后页面会自动换成新的——**不用手动刷新**。
3. 用**机器人小号**扫，扫完在手机上点「确认登录」。
4. 二维码下方会写「这张码生成于 N 秒前，约 M 秒后自动换新」。
5. 登录成功后整页变成大字：**✅ 已登录成功，可以关掉这个页面了**。

### 12.7.2 页面上的四种状态

| 状态 | 你会看到 | 意思 |
| --- | --- | --- |
| 等待扫码 | 黄点 + 「等待扫码」 | 拿手机扫就行 |
| 已扫码待确认 | 蓝点 + 「已扫码，请在手机上点『确认登录』」 | 手机端还差一步 |
| 换码中 | 图上盖着「换码中…」 | 上一张到期了，几秒内出新码，不用管 |
| 已登录成功 | 绿色大字提示 | 完事了，关页面 |

### 12.7.3 打不开怎么办

- 提示 404 / 打不开：地址里的 `qqqr-xxxx` 那段必须**一字不差**（这是防陌生人乱开的）。找 Bot 要完整地址。
- 页面能开但一直「暂时读不到登录状态」：说明服务器到 QQ 协议端的接口暂时不通，等 10 秒会自动重试；一直不行就找 Bot 看服务状态。
- 手机上扫码提示「登录风险 / 安全验证」：按提示做滑块、短信验证即可；提示「操作频繁」就等 10~30 分钟再扫，别连着扫。

### 12.7.4 运维要点（给改代码的人）

- 服务：`scripts/qr_portal_server.py`，只在本机 `127.0.0.1:18123` 上跑，由 nginx 用带 token 的路径反代到公网 https。
- 常驻：`systemctl status qqqr-portal`（`Restart=always`，机器重启也会自己起）。
- 换 token：改服务器上的 `.qqqr_token` 文件，再 `systemctl restart qqqr-portal`，同时把 nginx 里 `location ^~ /qqqr-<旧token>/` 改成新 token（`nginx -t` 通过后 `systemctl reload nginx`）。
- 彻底关掉：`systemctl disable --now qqqr-portal`，再把 nginx 里那段删掉并 reload。
- **别再用「每几秒强制刷新二维码」的循环**：强制刷新会让码的寿命只剩几秒，看起来就像刚给就过期。看板只读不刷，NapCat 自己约 2 分钟换一张。

## 十二点八、让阿凌用语音回你（2026-11-12 新增，小白版）

**阿凌现在默认就说语音**：不用发任何口令，重启后也还是语音。它会把回复按原来的「一句一条」节奏拆开，**每一句各发一条 QQ 语音**，中间还留原来的随机小停顿，不会一口气糊成一条长语音。想临时看文字，发一句 `文字模式` 就行。

### 12.8.1 三条口令（只有管理员能用）

| 你发 | 会发生什么 |
| --- | --- |
| `文字模式` | 之后的回复改回打字（管理员专用） |
| `语音模式` | 再切回语音（管理员专用，默认就是这个） |
| `语音状态` | 它告诉你现在是语音还是文字 |

说明：
- 口令本身**永远用文字回**（「切回文字了…」），这样你一眼就知道开关有没有生效。
- 默认是**语音模式**，重启服务器后保持上次的开关状态（状态存在插件自己的 `state.json`）。
- 普通群员发口令会被拒绝（「这个开关只有管理员能碰」）。
- 语音模式下，如果阿凌的回复里有图片、表情包这类非文字内容，那条就照常发文字；只有纯文字回复才转语音。
- 一条回复拆成几句就发几条语音，比如三句就是三条语音，按顺序连着到。

### 12.8.2 听到的是什么样

- 音色默认是**龙安小昕**（`longanxiaoxin`，22 岁亲切活泼音，元气少女），音量开到接口允许的最大值 `100`。
  之前用的龙安灵希（`longanlingxi`）你反馈听着偏老，已换掉；想换回去或试别的，见 §12.8.6。
- 只用**能念出来的正文**：`*揉着眼睛*`、`(￣^￣)`、表情符号、markdown 符号都会被去掉，不会念「星号 揉着眼睛 星号」。
- **动作描写不念**：像 `*揉眼睛*`、`（清了清嗓子，故意压低声音）` 这类舞台指示，整段只有动作就干脆不发那一条；动作和台词混在一段时，把动作剔掉只念台词。原因是语音模型没有表演能力，硬念出来反而怪。
- 拆句规则**沿用 AstrBot 原有的分段回复设置**（`cmd_config.json` 里 `platform_settings.segmented_reply`），改那边就等于改语音分条，不用动插件。
- 单句超过 120 字会按句末标点再切成几条，不会只念前一半。
- 默认**只发语音、不再重复发文字**；想两样都发，可以让 Bot 打开插件配置里的「语音之外再发一遍文字」。

### 12.8.3 合成失败会怎样

不会把消息弄丢：**自动退回发文字**，并把原因写进日志，例如
「合成失败，退回文字：HTTP 401: Invalid API-key provided」（密钥不对/没额度），
或者「HTTP 400 … [cosyvoice:]Engine error [411]」（音色名填错了）。

## 十四、排错清单

| 现象 | 先查什么 |
| --- | --- |
| NapCat 的连接一直「未连接」 | AstrBot 先启动了吗？URL 带 `/ws` 了吗？跨容器用了 `astrbot` 服务名还是错用了 `127.0.0.1`？ |
| AstrBot 日志从没出现「适配器已连接」 | 端口 6199 是否映射/占用；`ws_reverse_host` 是不是 `0.0.0.0`。 |
| 连上了，发消息没反应 | `enable_id_white_list` 是否为 false；群里是否真的 @ 到了机器人本体（不是群名片）。 |
| 回复「LLM 响应错误: ... 401」 | Key 无效/没填。看 provider 的 `key` 是否解析到了环境变量。 |
| 启动日志有 `Missing credentials` | provider 的 `key` 列表是空的，或 `$DEEPSEEK_API_KEY` 在容器里没有值。 |
| 改 `cmd_config.json` 后不生效/解析失败 | 文件是 UTF-8 **BOM**，用 `utf-8-sig` 读写；改完重启 AstrBot。 |
| 群里它开始乱插话 | 检查是否有别的插件/指令触发；本项目的预期是「只回 @ 和 `/` 指令」。 |
| WebUI 密码忘了 | 首次密码只在启动日志里打印一次；可删 `data/` 重新初始化（会丢配置和记忆）。 |
| 群里还是认错人 / 老问「你是谁」 | 看消息里有没有 `身份锚点(unified_id): … platform_id=<QQ号>`；没有就是插件没加载（`docker compose logs astrbot \| grep aling-memory` 应能看到「初始化完成」）。 |
| 长期记忆不生效 / 条目一直是 0 | 插件配置 `long_term_enable` 是否为 true、`long_term_scope` 是否 `owner_only`；`/mem status` 看当前 QQ 条目数；抽取每轮需要一次 LLM 调用，Key 不通时只会打 WARN 不报错。 |
| 记忆插件改了配置没生效 | 真正读的是 `data/astrbot/config/astrbot_plugin_aling_memory_config.json`（UTF-8 BOM），改完 `docker compose restart astrbot`。 |
| 加了管理员，但那个号还是「权限不足」 | QQ 号有没有写成**字符串**、有没有多空格？改完重启了吗？让那个号发 `/sid` 对照 `UID` 是否一致（群里 @ 一下再发 `/sid`）。 |
| 普通群友也能用 `/provider` / `/reset` | `admins_id` 里是不是误写了通配或空串；`unique_session=false` 时 `/reset`、`/new` 本来就只认管理员，普通人被拒是正常的。 |
| `/mem status` 提示「只有管理员能看」 | 1.0.2 起的总览只给管理员；普通成员用不带参数的 `/mem facts` 看自己那份。 |
